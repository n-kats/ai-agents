# ドキュメント作成ガイドライン（レガシー）

このドキュメントは旧設計を対象としたドキュメント運用方針の記録です。現行ガイドラインは `docs/meta_plan/` のテンプレートや `docs/` 直下の資料を参照してください。

## 基本方針

- **一貫性**
  - ドキュメントは形式や文章のスタイルを統一して記述する。
  - プロジェクトの直接の成果物には含まれない方針・規約・内部設定・設計指針などは `docs/meta_plan/` に記録する。
  - 利用方法や手順などの具体的なコマンド説明は `docs/usage/` に記録する。
  - プロジェクトの目的物を作るための計画・設計情報は `docs/plan/` に記録する。

- **明確さと簡潔さ**
  - 情報は誰でも理解しやすいように明確かつ簡潔に記述する。冗長な説明は避ける。

- **リンクの活用**
  - 関連ドキュメント間は相互リンクを貼り、参照性を高める。

- **更新と履歴管理**
  - 内容に変更があった場合は速やかに更新し、変更履歴を追跡できるようにする。

## ドキュメンテーション整理

- **全体的な目的とエージェントに依存しない事項**
  - プロジェクト全体またはツールに適用可能で、特定実装に依存しない形で文書化する。
- **エージェント固有の実装詳細**
  - 特定のモジュールやエージェントの実装ガイダンスは別途文書化する。
- **文書構造**
  - 一般的な目的と具体的実装の詳細を分けて整理し、必要に応じて目次を用意する。
- **更新と改訂**
  - プロジェクト構造の変更に合わせて定期的に見直す。

## その他の指針
- タイトルと見出しを活用し、論理的な構造を保つ。
- コード例やコマンド例はコードブロックで示す。
- 設定項目一覧などは表形式で整理し、比較しやすくする。

この資料は歴史的な整備方針を残す目的のため、最新手順とは異なる場合がある点に注意してください。
