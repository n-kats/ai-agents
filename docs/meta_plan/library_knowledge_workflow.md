# ライブラリノウハウまとめワークフロー

## 目的
外部ライブラリに関する知見や検証結果を「汎用的に再利用できる形」でドキュメント化し、後続作業の指針とする。採用・不採用を問わず得られた判断材料を整理し、同様の調査を繰り返さないことが狙い。

## トリガー
- 外部ライブラリの評価や検証を行った結果、実践的なナレッジが得られた。
- 運用に組み込むライブラリの使い方、制約、ベストプラクティスを共有したい。
- 過去の検証が参照しづらく、新規メンバーが同じ検証を繰り返しそうな状況。

## 手順
1. **既存資料の確認**  
   - `docs/libs/` に同ライブラリの資料が存在しないか確認する。既存ドキュメントがあれば追記で整合性を保つ。
2. **ドキュメント作成・更新**  
   - ライブラリ名をファイル名とした Markdown を `docs/libs/<library>.md` に作成／編集する。  
   - 採用した手法・採用を見送った手法・注意点など、判断理由を含めて記録する。  
   - プロジェクト固有のコードや設定値には触れず、汎用的に適用できる知見のみを書く。
3. **関連ドキュメントとの同期**  
   - 仕様変更や運用ポリシーに影響する場合は、必要に応じて `docs/implementation_status.md` や機能別ドキュメントも更新する。
4. **周知**  
   - 関連する Issue／PR から該当ドキュメントを参照し、チームに共有する。

## 運用ポリシー
- ドキュメントには日付やバージョンなどのコンテキストも記載し、陳腐化を防ぐ。
- 再調査や追加検証を行った場合は同じドキュメントを更新して履歴を一本化する。
- 決定事項と未確定事項を明示し、後続の調査タスクがあれば TODO などで残す。
