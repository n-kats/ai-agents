# Mermaid 図作成の振り返りメモ

このドキュメントは、複数プロジェクトでマーメイド図を活用する際の共通的な反省点と改善策をまとめたものです。新しい図を描画する前に読み返し、品質向上と再作業の削減に役立ててください。

## よくある課題
- **構造定義と表現の乖離**：ディレクトリ構造と論理アーキテクチャを混同し、読者が意図を汲み取りづらくなる。
- **GitHub レンダリングエラー**：改行や特殊文字のエスケープ忘れにより、`Parse error on line...` などのエラーが発生する。
- **過剰なノード配置**：視認性を下げるほどラベルやサブグラフを詰め込み、メッセージがぼやける。
- **図とテキストの不整合**：図を更新しても周辺ドキュメントに反映しないため、読者が情報を信用できなくなる。

## 改善のヒント
- **目的の再確認**：描きたい概念が「物理配置（ディレクトリ）」「論理構造」「処理フロー」のどれかを明確化する。
- **ラベルの HTML 改行活用**：GitHub Flavored Markdown では `"Label<br/>detail"` といった形式で改行を表現する。
- **軸の一貫性を設計**：抽象→具体や概念→実装などの方向性を決め、ノード配置や矢印が読み手の期待と一致するようにする。
- **段階的な図解**：密度が高い場合は複数図に分割し、読者が段階的に理解できるようにする。
- **テキストとの同期**：関連する仕様書・ガイドに必ずリンクや更新履歴を記述し、図との齟齬を防ぐ。

## 作業前チェックリスト
1. 図のスコープと粒度を決定したか。
2. Mermaid の方言（GitHub / GitLab / Docusaurus など）の差異を確認したか。
3. ノード名・ラベルに不要な制御文字やエスケープ漏れがないか。
4. 変更後に関連ドキュメントへ反映する箇所を洗い出したか。
5. レビューアが理解しやすい説明文（添え書き）を用意したか。

## 作業後レビュー
- 生成物を実際にプレビューし、レンダリング結果を確認する。
- 伝えたい情報と図の構造が一致しているか第三者視点で見直す。
- 発生したエラーや指摘事項をこのメモに追加し、知見を蓄積する（例: 抽象層は上、具体層は下に配置するなどの再発防止策）。

## 今後の検討事項
- Mermaid 記法の共通テンプレート（サブグラフ構造や色設定）を整備し、使い回しを容易にする。
- 図のバージョン管理方法（ファイル内コメントや更新履歴の明文化）を検討する。
- Mermaid 以外のツール（Draw.io 等）との併用ポリシーを定め、用途に応じた選択基準を共有する。
