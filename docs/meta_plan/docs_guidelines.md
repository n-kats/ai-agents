# ドキュメント作成ガイドライン

このドキュメントは、本プロジェクトにおけるドキュメントの書き方や記録方法についての基本方針を示します。目的は、すべての情報を一貫性を持って整理し、どのプロジェクトでも利用可能な形で記録することです。

## 基本方針

- **一貫性**  
  ドキュメントは、形式や文章のスタイルを統一して記述します。各ディレクトリは、対象となる内容に応じて分けられます。  
  - プロジェクトの直接の成果物には含まれない、方針や規約、内部的な設定、設計指針などの情報は `docs/meta_plan` に記録します。
  - 利用方法や手順などの具体的なコマンド説明は `docs/usage` に記録します。
  - プロジェクトの目的物を作るための計画・設計情報は `docs/plan` に記録します。

- **明確さと簡潔さ**  
  情報は誰でも理解しやすいように、明確かつ簡潔に記述することを心がけます。冗長な説明は避け、必要な事項のみを記載します。

- **リンクの活用**  
  関連するドキュメント間は、相互にリンクを貼ることで情報の参照性を高めます。例えば、Makefileのポリシーについては [docs/meta_plan/makefile_policy.md](./makefile_policy.md) を参照してください。

- **更新と履歴管理**  
  ドキュメントの内容に変更があった場合は、速やかに更新し、その履歴を記録できるようにすることが望ましいです。

## ドキュメンテーション整理

- **全体的な目的とエージェントに依存しない事項**:
  - プロジェクト全体またはツールに適用可能で、特定の実装に依存しない形で文書化する必要があります。
  - 目的、基本構成、利用シナリオ、技術的特徴など、特定のモジュールやエージェントに結びつかないセクションを含めます。

- **エージェント固有の実装詳細**:
  - 特定のモジュールやエージェントの実装に関する明確なガイダンスを提供するために、別途文書化する必要があります。
  - モジュール構成、特定のエージェントの役割、および実装に特化した情報を含めます。

- **文書構造**:
  - 一般的な目的と具体的な実装の詳細を別々の文書にすることで、混乱を避け、簡単にナビゲートできるようにします。
  - 各文書には明確なタイトルを付け、必要に応じて目次を含めます。

- **更新と改訂**:
  - プロジェクトの構造や目的の変更を反映するために、定期的にドキュメンテーションを見直し、更新します。
  - 実装の変更は、適切な文書に反映されていることを確認します。


- **タイトルと見出し**  
  各ドキュメントは、タイトルと適切な見出しを利用して論理的な構造を持たせます。
  
- **コード例**  
  必要に応じ、コード例やコマンド例はコードブロックを使用して記述します。  
  例:
  \`\`\`
  make lint TARGET=src
  \`\`\`

- **表形式の情報整理**  
  複数のコマンドや設定項目を一覧で示す場合、表形式を利用して、視認性と比較しやすさを向上させます。

このガイドラインに従って、各ドキュメントを作成・更新してください。プロジェクト全体で統一されたドキュメント体系を維持することが、情報の共有と再利用性を高める鍵となります。
