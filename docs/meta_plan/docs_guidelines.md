# Documentation Guidelines Template

本ドキュメントは複数プロジェクトで再利用可能なドキュメント作成ガイドラインのテンプレートです。個別リポジトリでは、ここで述べる方針を土台にプロジェクト固有の運用ルールを別ファイルへまとめてください。

## 基本方針
- **一貫性**: タイトルや見出しレベル、箇条書きスタイル、口調などを統一する。
- **明確さと簡潔さ**: 必要な情報に集中し、冗長な説明は避ける。詳細は補遺や別ドキュメントへ分離する。
- **リンク活用**: 関連ドキュメント同士は相互リンクで結び、参照性を高める。
- **履歴管理**: 更新日や対応する Issue/PR を明記し、変更意図が追跡できるようにする。

## ドキュメント分類のヒント
- **仕様・設計**: 現行アーキテクチャやコンセプトは主要ドキュメントにまとめる。
- **ガイドライン**: コーディング規約やドキュメントポリシーなど、プロジェクト横断で使える情報は再利用しやすい場所に配置する（例: `docs/meta_plan/`）。
- **運用手順**: CLI コマンド、デプロイ手順、トラブルシューティングは利用者向けセクション（例: `docs/usage/`）へ切り出す。
- **レガシー資料**: 旧仕様や検証ログは専用ディレクトリ（例: `docs/legacy/`）へ移して注意書きを付ける。

## 運用例
1. プロジェクト固有のフローやツールチェーンは `docs/` 直下にまとめ、テンプレート類は `docs/meta_plan/` で保守する。
2. 他プロジェクトへ転用する際は、このテンプレートをコピーしてディレクトリ構成や命名規則を調整する。
3. 文書構造が複雑になった場合は、索引や目次、セクション分割を追加して可読性を維持する。

## 更新のすすめ
- 大きな構成変更やリリース時に定期レビューを行い、不要になった情報を整理する。
- ドキュメントがプロジェクト固有になりすぎた場合は、共通化できる部分を抽出してテンプレートに反映する。
